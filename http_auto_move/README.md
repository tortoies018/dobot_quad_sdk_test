# MH4 HTTP Auto Move

这是 `auto_move` 的 HTTP 运动控制版本。摇杆、动作状态、急停和 IMU 全部通过
《MH4 HTTP接口定义》下发或读取；只读 gRPC 用来获取 HTTP 没有提供的世界坐标，
用于绘制实际 3D 轨迹。

- `POST /connection/state`：声明客户端连接；
- `GET /protocol/exchange`：以 5 Hz 获取状态并保持连接占用；
- `POST /settings/movement/joystickControl`：以固定 10 Hz 发送带新毫秒
  `timestamp` 的摇杆值；
- `POST /settings/movement/action`：可选地在开始前进入 WALK/RL 等运动状态；
- `POST /settings/emergencyStop`：触发或解除软急停；

## 启动

在仓库根目录运行：

```bash
python3 -m http_auto_move.main
```

也可以直接运行：

```bash
python3 http_auto_move/main.py
```

依赖项目已有的 `PySide6`、`pyqtgraph`、`PyOpenGL` 和 `dobot_quad`。
HTTP 客户端本身使用 Python 标准库。

当前机器狗地址和文档固定地址：

- 当前机器狗：`10.30.12.196:22000`
- AP：`192.168.1.6:22000`
- 网线直连：`192.168.5.2:22000`

## 首次使用

1. 让机器人处在开阔、安全并可随时断电的位置。
2. 先连接，确认右侧 `exchange` 心跳和急停状态持续更新。
3. 首次使用建议把摇杆幅值设为 2000～5000、持续时间设为 0.5 秒。
4. 选择前后来回、左右来回或左右旋转；一组会依次完成两个相反方向。

连接方式默认使用“自动检测”：程序先读取 `/connection/type`，再把实际的
`AP` 或 `Station` 写入 `/connection/state`。使用 `192.168.5.2` 网线地址时应显示
`Station`，不要登记为 `AP`。

当前默认映射来自点足 miniQuad 实机标定：

| 动作 | HTTP 字段 | 默认值符号 |
| --- | --- | --- |
| 前进 / 后退 | `btn_move.y` | 正 / 负 |
| 左移 / 右移 | `btn_move.x` | 负 / 正 |
| 左转 / 右转 | `btn_turn.x` | 负 / 正 |

## 界面参数

- `摇杆幅值`：直接发送给 HTTP 接口，范围 500～32767，绝对值越大通常越快；
- `每方向持续时间`：两个相反方向使用相同时间，使一组的理论终点回到起点；
- `执行组数`：完整双向动作重复多少组；
- `动作间隔`：一个方向归零后，到下一个方向开始前的等待时间；
- `运动状态`：开始前通过 HTTP 切换到 WALK、RL 或 FLYING_TROT；
- HTTP 摇杆固定以 10 Hz 发送，不需要用户设置发送频率。

程序不再显示“满幅标定速度”和“算法速度比例”。前者原本只是把距离换算成
开环时间用的实测速度，后者是 22002 算法服务的全局速度设置，都不是
`joystickControl` 请求的必需参数。

### 运动范围限制

“运动范围限制”位于左侧“执行参数”下面，不是一个独立动作，支持矩形和多点
两种围栏，并分为“尺寸围栏”和“标点围栏”两个选项卡。矩形围栏设置长度和宽度
后，点击“以当前位置设定矩形”，程序会把
当时的 gRPC 世界坐标作为中心，把当时 HTTP `exchange.imu.rpy` 的偏航角作为
长边方向。多点围栏可让机器狗依次移动到边界位置，每到一处点击“记录当前位置”；
至少记录 3 个点后点击“生成多点范围”。程序会自动计算所有标点的凸包，因此
标点顺序不限，位于范围内部的点不会成为边界顶点。之后仍然使用原来的前后、
左右或左右转动作，重复次数也仍由“执行组数/无限循环”控制。

- 3D 视图用青色轮廓显示限制范围、黄色点显示中心、紫色点显示人工标点；
- 自动来回动作以 10 Hz 检查实际位置，未越界时不改变原动作时序；
- 检测到越界后立即重复发送全零摇杆，停止当前方向，再插入一段闭环回中心指令；
- 紫色线和目标点显示当前回中心指令；回到中心后继续动作组中的后续方向；
- 每个普通方向继续使用原有误差日志，回中心完成或失败也会打印中心误差；
- 范围限制启用后，gRPC 位置过期会停止动作；回中心时 HTTP IMU 或 gRPC 位置
  超过 1 秒未更新会立即归零并等待恢复；3 秒内恢复则继续回中心，否则中止，
  不会使用旧坐标盲走；
- 点击“取消限制”即可恢复完全不限制范围的原有行为。
- “清除标点”只删除尚存的人工标点，不会自动取消已经生成并启用的多点范围；
  如需停用范围，请点击“取消限制”。

### 范围内随机巡逻

在“自动动作”中选择“随机巡逻”，并先启用矩形或多点围栏。巡逻按独立路段执行：
程序在安全内缩后的围栏中按面积随机抽取一个目标点，不再比较候选点距离，也不再
优先选择远点；随后根据 HTTP IMU 原地转向该点，再只向前移动设定的路段长度，
停车后才随机规划下一段。为避免无效微小动作，只会排除与当前位置近到低于定位
容差的点。

- “巡逻速度”是前进幅值，也决定转向短脉冲的强度；转向脉冲下限取 8000 与
  设定速度一半中的较大值，但不会超过设定速度。每个脉冲后归零并重新采样航向，
  避免低幅值卡在实机摇杆启动死区；
- “每段长度”是转向完成后计划向前移动的距离；“执行组数”表示巡逻路段数量，
  “无限循环”表示持续规划新路段；
- “偏航误差死区”是允许的转向残差；首次转向超时后若绝对偏航误差仍超过死区，
  程序会归零并补转一次。补转后若只剩小幅残差，会降低前进速度并在前进中继续
  纠偏；残差超过安全纠偏上限（最多 15°）时才中止巡逻；
- 如果当前围栏空间不足以容纳完整路段，该段会自动缩短到安全目标，而不会越过
  围栏追求设定长度；
- 前进阶段不使用横移，只发送正向 `move_y`，同时用小幅 `turn_x` 抑制偏航漂移；
  航向误差较大时会自动降低前进幅值，航向收敛后恢复设定速度；
- 巡逻途中仍以 10 Hz 检查实际位置；检测到越界时立即归零、回到范围中心，
  然后重新规划该序号的路段。回中心使用独立的限速和近中心减速，不会直接沿用
  过高的巡逻速度；若完整回中心时限结束时仅剩小幅定位误差，进入近中心缓冲区后
  可继续巡逻，明显偏离中心时仍会中止；
- 位置或 IMU 短暂失鲜时会停车等待恢复，持续不可用、转向/前进超时或回中心失败
  时中止巡逻。

该功能依赖可靠的世界坐标，仅是软件保护。首次使用请设置较大的安全余量、较低
摇杆幅值，并保留现场急停和实体安全隔离。

## 全部 HTTP 接口选项卡

“全部 HTTP 接口”是按钮式控制台，收录接口文档中的 112 个方法/路径组合。
可按分类筛选或按名称搜索；蓝色按钮是读取接口，橙色按钮是普通控制接口，
红色按钮是高风险控制接口。控制器接口自动使用 `22000`，`/algs/*` 算法接口
自动使用 `22002`。

点击接口按钮后，程序会根据文档示例生成参数控件：布尔参数使用勾选开关，
枚举参数使用下拉框，数值参数使用调节框，文本参数使用普通输入框，不需要
编辑接口路径或编写 JSON。

- 请求在后台执行，超时不会卡住界面；响应同时显示在选项卡和日志中；
- 手动调用摇杆接口时，程序会自动补充新的毫秒 `timestamp`；
- 局域网音频的 multipart 接口使用“选择文件”按钮，不需要填写文件路径或表单；
- 密码和图传令牌在日志里会显示为 `***`；
- 带 `⚠` 的运动、标定、OTA、网络配置、删除和工程接口始终要求二次确认。

## 轨迹与状态

- exchange 状态区使用双列紧凑布局，减少对 3D 轨迹区域的纵向占用；“温度”
  选项卡显示 IMU、BMS PCB/AFE，以及四条腿各关节的伺服板、MOS 和电机温度；
- 3D 轨迹的位置来自同一机器人 `:50051` 的只读 gRPC `pos_body`；
- “总里程”按本次自动动作期间相邻 `pos_body` 的 XY 平面距离累计，“总时间”从
  点击“开始”计到动作完成、停止或急停；两者每次开始新任务时清零，清除 3D
  轨迹不会清零统计；
- 3D 本体姿态轴以及界面的 RPY、陀螺仪、加速度均来自 HTTP
  `exchange.imu`，不使用 gRPC IMU；
- 不单独显示动作状态面板。每个方向开始和归零时，日志用 `↑ ↓ ← → ↺ ↻`
  打印方向、实际 HTTP 摇杆值、持续时间和发送频率；
- 每个方向结束后，日志打印实际位移或转角以及侧向、位置、姿态漂移；每个完整
  来回组结束后打印相对组起点的平面、3D 和偏航回零误差；
- 位移误差依赖 `:50051` 的实际位置，角度误差依赖 HTTP IMU；任一数据源不可用时，
  日志会明确提示无法计算对应误差，不会用指令值冒充实测值；
- “摇杆归零”会中止当前动作并重复发送全零摇杆值；“急停”另外调用软急停接口。

程序不会自动解除软急停。解除前请先确认现场安全。
